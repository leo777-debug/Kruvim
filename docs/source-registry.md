# Source registry: imports and licence checklist

Checked 2026-10-04. No demographic observations are seeded. Registration is not permission to reuse a resource. Production weighting requires an active source and recorded platform-admin commercial licence approval.

World Bank UAE indicator API returned HTTP 200; its indicator page explicitly publishes CC BY 4.0. The native survey years and missing cells are preserved. Generic bounded CSV/XLSX download and parsing adapters support explicitly mapped public resources. FCSC SDMX endpoint returned HTTP 403: use an authorised manual export; no restrictions are bypassed.

## Manual import

1. Data pool → Survey data: choose the registered publisher.
2. Upload the original CSV/XLSX (export formulas as values).
3. Map value, metric, units, geography, dimensions and native period. Preview; missing figure cells are counted and skipped.
4. A platform admin applies the observations. Original bytes stay in local/S3 object storage and raw_ref identifies the retained asset.
5. Separately record commercial licence evidence and activate the source in Sources. Importing does not imply approval.

Public reference observations are global; workspace files and mappings remain private. Identical cells are idempotent; revised values remain separate. Proxy school enrolments, property prices, ridership and migrant deployment flows never silently become resident counts or income shares.

## Native UAE model mappings

Use `population_share` with `percent`/`fraction`, or `population_count` with `persons`/`count` and a separate `population_total` matching the same publisher, geography, period start and period end. No denominators are guessed. Source configuration `population_dimension_map` maps a publisher's codes to canonical dimensions without changing stored native observations, e.g. `{"gender_code":{"dimension":"sex","values":{"M":"male","F":"female"}}}`. Canonical residence/work emirates are `AE-DXB`, `AE-AUH`, `AE-SHJ`, `AE-NE`. `AE` remains their weighted union.

`remittance_share` and `platform_share` require explicit native fractions/percentages; platform cells specify a canonical `platform` (including `whatsapp`). `salary_day` requires an explicit day-of-month cell with unit `day`. These metrics are never inferred from aggregate credit/remittance amounts or advertisement reach. Missing attributes retain placeholder/unknown support. A visitor layer requires a resident/visitor **stock** marginal; arrivals by month/source-country do not establish such a share. Unavailable visitor data produces no invented visitor layer.

Reconciliation ranks native cells by editable source reliability, recency and geography match. Conflicts retain competing values, select a documented target rather than averaging disagreement away, and widen model uncertainty. Bounded IPF/raking fits available joint/conditional cells; missing code mappings and non-convergence are gaps, with failed fits labelled placeholders. Admins rebuild, inspect source/conflict/coverage receipts, activate and can roll back to ready approved versions. These confidence heuristics are not a measured accuracy guarantee.

## Festivals, schools and events

Import approved `calendar_event`, `school_term` or `regional_event` cells with exact event dates in `period_start`, native `period_end`, geography and a `name` dimension. Optional dimensions include `calendar_membership` and `language`. The connector links each date back to its observation and original asset. KHDA/ADEK and city event portals remain pending where no approved public feed/date file is loaded. Diwali/Onam/Christmas show **date source pending** instead of invented future dates. The month-end spending cycle is a clearly labelled model calendar rule; it does not assert a resident's salary day.
