# Browser-local processing verification — 17 November 2026

This is the initial `523a3f8` verification. See the [follow-up report](browser-local-followup-2026-11-17.md) for paid-provider checks and the new conservative memory policy.

Implementation is on branch `feat/browser-local-files-20261117`, based on the source used for the 17 November production release (`8e9aab5`). The other workspace checkouts and their uncommitted work were not changed. No deployment or billing/storage-plan change was performed.

## Scope and environment

Story: select content/background files → prepare on the laptop → review editable text and selected images → send derived JSON to Kruvim's existing API → build the content card/knowledge graph → complete the audience simulation and display results.

Tests used real generated documents, encoded image/audio/video files, actual native browser decoding, PDF.js, and real browser ONNX Whisper inference. Speech was generated by Windows System.Speech, not a mocked transcription result. Large media/image/PDF fixtures contain actual encoded content; sizes were not merely spoofed in upload metadata.

- Windows desktop, HP EliteBook 840 G5, Intel64 Family 6 Model 142 Stepping 10, approximately 40 GiB physical RAM.
- Installed Chrome 157 and Edge 157, controlled headlessly by Playwright.
- Disposable local FastAPI/SQLite verification server, external data feeds disabled, existing deterministic dry-run simulation provider. Production API/database/accounts were not modified.
- Development-server tests and separate tests of the compiled build served under `/app/`, matching the deployed frontend base path.

## Browser network inspection

Playwright inspected browser-context request events, including worker requests, during local preparation and after review. Local preparation/transcription emitted **zero POST/PUT/PATCH/DELETE requests** in the extraction matrix. Public model/runtime downloads were GET requests. App login/session refresh and population-count requests were separately recognizable ordinary app traffic in authenticated flows; their payload contents were not written into evidence.

The compiled-production matrices inspected every non-GET request and found no upload-authorization/completion calls, multipart bodies, original documents/images, or raw audio/video transfers. Simulation content explicitly had `asset_id: null` and empty `asset_ids`. Backend schema validation additionally decodes and verifies selected JPEGs and rejects video/audio data URLs, invalid images, oversized dimensions and invalid timestamps.

Representative compiled-build simulation requests:

| Source | Source bytes | Derived JSON bytes |
| --- | ---: | ---: |
| Large PDF | 57,620,194 | 936 |
| DOCX | 36,653 | 849 |
| Large PNG | 57,659,494 | 334,773 |

Browser JPEG encoding accounts for the different frame payload sizes. The transcript-plus-selected-frame completed-simulation checks also recorded their request sizes and content structure. These observations verify the tested paths and files, rather than asserting that every possible browser extension, compromised device, future client or legacy API cannot transmit data.

Evidence is in the sibling directory `../kruvim-local-processing-evidence/`: `edge-local.json`, `chrome-local.json`, `*-flow.json`, `*-production.json`, `*-carousel.json`, `*-failures.json`, `*-cancel-download.json`, and `*-review.png`. Evidence contains synthetic text and request metadata, not passwords, authorization headers, refresh-token bodies, or provider credentials. Large fixtures are kept outside Git.

## Errors found and fixed

1. Vite's default IIFE worker output could not handle dynamic document imports. Workers now build as ES modules.
2. Running PDF.js inside a wrapper worker exposed PDF setup messages as if they were completed text. PDF.js now owns its parsing worker; extraction coordinates pages explicitly and worker completion messages are checked.
3. An MPEG-4 Part 2 test fixture was unsupported by the browser. The real supported fixture is H.264/AAC; missing video dimensions now produce a codec-specific conversion/transcript error.
4. Cached speech weights still depended on a CDN-hosted runtime. Runtime JavaScript/WASM are now bundled with Kruvim, and the external-network-blocked regression passes.
5. Browser-derived media could be lost on draft edit, and new carousel slides needed to preserve existing slides. Derived state now survives edit and ordered append; A/B regression checks cover it.
6. Native decode cannot be forcibly aborted. Cancellation now rejects immediately, closes the context and discards late native results, with the browser limitation documented.
7. Test traces written inside the frontend directory triggered Vite HTML reloads during testing, and concurrent test runs initially clobbered trace output. Generated output is now ignored by Vite/Git and independent reruns use separate output directories. The affected scenario passed on rerun. Earlier failed artifacts were not counted as passing checks.

## Limits and work not verified

- No paid cloud text/vision model calls were made. Browser-to-API-to-simulation behavior used the real application with its labelled dry-run provider, and cloud vision received an adapter contract test. This does not validate paid model availability, model quality, credentials, account quotas, or production inference.
- Actual 4 GB/8 GB machines, real OS memory pressure/kills and maximum-size media at every safety ceiling were not tested. Memory-pressure/error checks inject capability/allocation failure conditions; they are not physical low-RAM stress tests. JavaScript cannot reliably recover from a killed tab/process.
- Only the stated Windows desktop browsers/codecs were qualified. Safari, Firefox, mobile, other OSes, WebGPU, unusual channel layouts/codecs and multilingual recognition quality were not verified. Speech uses WASM rather than requiring WebGPU.
- The full device was not taken offline. The model-hosting-independent cached case was tested; the website is not promised to work offline without all required page/runtime assets already available.
- Scanned/protected PDFs, OCR, DOCX visual layout/headers/footnotes, embedded document images and complete-video scene coverage are not implemented. Plain text/transcripts/local conversion are explicit alternatives.
- Native audio decode buffers the source, and sparse video samples cannot establish what happens between selected frames. Whisper tiny misrecognized the product name and emitted `[BLANK_AUDIO]` markers on silence; review/edit remains necessary.
- The entire repository test suite was not run. Focused checks cover the changed workflow and its backend compatibility paths. No new deployment was made.

## Reproducing

Generate fixtures from the repository root using a Python environment with reportlab, python-docx and Pillow, Windows System.Speech, and FFmpeg on PATH:

```powershell
python frontend/tools/create-local-processing-fixtures.py
```

Start the isolated backend from `backend/`:

```powershell
$env:KRUVIM_VERIFY_PORT = "8016"
python -m tools.serve_verify
```

Start Vite from `frontend/` in another terminal:

```powershell
$env:KRUVIM_API_URL = "http://127.0.0.1:8016"
npm run dev -- --host 127.0.0.1 --port 5186 --strictPort
```

Run the development browser checks from `frontend/`:

```powershell
npx playwright test --config playwright.local.config.ts
```

Build and serve the production assets from `frontend/`, then run the separate production configuration:

```powershell
npm run build -- --base=/app/ --outDir dist/app
npm run preview -- --outDir dist/app --base=/app/ --host 127.0.0.1 --port 5187 --strictPort
```

```powershell
npx playwright test --config playwright.local-production.config.ts
```

Focused backend tests, from `backend/`:

```powershell
python -m pytest tests/test_browser_local_content.py tests/test_media_processing.py tests/test_content_links.py tests/test_e2e_dry.py tests/test_direct_uploads.py -q
```
